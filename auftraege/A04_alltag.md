Nachtrag zu A04 (bitte mit in auftraege/A04_alltag.md aufnehmen), Teil 4 — Fernzugriff vom zweiten PC ohne Fremdpaket. Ziel (Lastenheft Vorgang 6, Phase 2): Claude Desktop auf dem zweiten Windows-PC soll PostKauz auf dem Büro-PC über Tailscale nutzen (mcp --http hinter tailscale serve, Modus key). Claude Desktop bindet in claude_desktop_config.json nur stdio-Server ein; Remote-Connectoren laufen über Anthropics Cloud und erreichen das Tailnet nicht. Statt einer Fremdbrücke (npx mcp-remote: Lieferkette, Schlüssel im Klartext in der Konfiguration) baut PostKauz die Brücke selbst:
- postkauz remote add <name> --url <https-URL bis /mcp> --key-stdin: Ziel in der Konfiguration ([remote.<name>] url), Schlüssel nur im Schlüsselbund (wie Kontopasswörter; nie als Argument, nie in Datei/Log/Audit/Fehlermeldung), zurücklesen und vergleichen. Dazu remote list, remote remove <name>, remote test <name> (initialize + tools/list, zeigt Zahl der Tools und Rolle aus policy, kein Inhalt).
- postkauz mcp --remote <name>: stdio-MCP-Server, der jede JSON-RPC-Nachricht 1:1 an den entfernten Streamable-HTTP-Endpunkt weiterreicht (Authorization: Bearer aus dem Schlüsselbund; Mcp-Session-Id und MCP-Protocol-Version übernehmen; Antworten als JSON oder SSE; Server-Nachrichten über GET-Stream, falls angeboten; Abbruch/Cancel durchreichen). Öffnet keine Datenbank, braucht kein Datenverzeichnis, liest kein Mailpasswort. Nur https; http nur für Loopback (Tests). Zertifikat normal prüfen. Fehler als JSON-RPC-Fehler an den Client mit verständlichem Text (nicht erreichbar, 401 Schlüssel ungültig, 404 Sitzung abgelaufen → neu initialisieren oder klarer Fehler).
- Bevorzugt das offizielle Go-MCP-SDK aus go.mod (Client-Transport + Stdio), keine neue Abhängigkeit ohne Begründung. Tests gegen mcp --http in-process (httptest): Tools-Liste und ein Suchaufruf gehen durch, falscher Schlüssel → klarer Fehler, Schlüssel erscheint in keiner Ausgabe (Kanarientest).
- Doku: docs/betrieb.md Abschnitt 4.9 (Windows-PC als Knoten, dauerhaft statt vorläufig) mit Schritt-für-Schritt für beide PCs: Büro-PC (mcp --http als geplante Aufgabe, [http] resource, tailscale serve --bg 8787) und zweiter PC (remote add, Eintrag in claude_desktop_config.json mit command = Pfad der postkauz.exe und args ["mcp","--remote","<name>"], ohne env mit Schlüssel); docs/cli.md, docs/mcp.md, docs/sicherheit.md (neuer ausgehender Client, Schlüssel nur im Schlüsselbund).
